# 人间三卷

> 你不在此时此地

三个纯静态网页，一个总入口。写的都是同一件事：**人怎么在别处活下去**。

- 一卷让你**查**——如果睁开眼在另一个时代，该干什么；
- 一卷让你**活一遍**——投胎到秦至清，把一生过完；
- 一卷让你**承认自己放弃了什么**——现代人的岔路，十分钟走完一生。

不联网、不登录、不收集任何数据、没有后端。双击 `index.html` 就能打开，也可以上传到 Cloudflare Pages 变成一个网址。

---

## 一、想法：这三卷为什么放在一起

三个站最初是分开做的，但它们其实是同一个问题的三种问法：

|            | 问法                | 你的位置   | 时长       |
| ---------- | ----------------- | ------ | -------- |
| 卷一《穿越求生指南》 | 那样的日子**怎么过**？     | 局外人，翻书 | 随时查      |
| 卷二《生在何朝》   | 那样的日子**轮到我**呢？    | 局中人，投胎 | 一局 30 分钟 |
| 卷三《如果当时》   | **这辈子**我怎么走到这儿来的？ | 现代人，回望 | 一局 10 分钟 |

摆在一起，读者能从"看别人怎么活"一路走到"看自己怎么选"。所以门户本身不做任何事，只做一件事：**把三卷摊开在桌上**。

门户的视觉是宣纸浅色书卷风（暖白纸面 + 朱红印章 + 宋体），刻意不统一三站各自的视觉——三卷本来就该长得不一样。

## 二、三卷各是什么

### 卷一 · 穿越求生指南（已成型）

按时代分册的野外手册。**21 个时代**，从新石器一路到当代中国，**515 条内容、93 个配方、151 种身份**。

每个时代固定七章：落地须知 / 你是哪一种人 / 政局·大事·站队 / 以当时的水平能造什么 / 致命雷区 / 失效的东西（仅当代六题）/ 行动清单。

- 目录页 `index.html`：时代卡片 + 分组筛选 + 全站搜索
- 详情页 `era.html?id=qin`：一个时代一页，左侧目录随滚动高亮，`←` `→` 切上下站
- 配方、步骤、清单一键复制；可打印

### 卷二 · 生在何朝（进行中，v0.8）

秦至清 **19 个政权**全部可玩，**1669 条事件 / 51 个数据包**。回合制经营，不是旁观。

抽签 → 出生卡（哪一朝、哪一地、哪一户人家）→ 26–30 回合 → 死亡回顾。八等人家（宗室、勋贵、吏家、士、商、农、佃、贱籍）各有各的活法与死法。天下卡五页：舆图 / 势力 / 军备 / 官职 / 本朝。

**铁律**（不随版本改动，改之前先想清楚会破坏什么）：

1. 秦至清 19 个政权，**全部可玩，一个不能少**。可以晚做，不可以少做。
2. 回合制经营，不是看故事。有数值、有得失、有长线回响。
3. **不看他人剧本**：无后端、无排行榜。但"千局对照"保留（本地纯函数跑 1000 次，不涉及他人数据）。
4. 残酷设定全保留（溺婴、卖儿鬻女、屠城），统一用记事体：保留事实、删掉细节、不抒情、不弹确认框。
5. 浅近白话打底，关键处用当时词汇并加小注。**禁现代词**（资源 / 效率 / 战略 / 人脉值 / 好感度 / 升级 / 属性）。

### 卷三 · 如果当时（进行中，v1.0）

现代人的电车难题。**146 道岔路（96 二选一 + 50 多选）、30 个事件、14 组连锁、20 种结局**，一局走 6 道，约 10 分钟。

核心不是"选对"，是**后悔**：每次选择都让你看清背后放弃了什么，结算时把"这一生你放弃了 X"一条条列出来。

- 四层设计：钩子（标题即传播素材）→ 核心循环（开局设定 → 岔路卡 → 即时反馈 → 跨关卡连锁 → 结局结算）→ 留存钩子（放弃清单 / 结局收藏 / 随机开局）→ 视觉叙事（暗色命运牌局，**红色＝得、绿色＝失**）
- 跨关卡连锁：第 3 关放弃清华，第 9 关就有老同学聚会局

## 三、硬约束（决定了全部技术选型）

这几条不是偏好，是**不能违反的前提**，改动前先想清楚会破坏什么。

| 约束                | 原因                  | 后果                                             |
| ----------------- | ------------------- | ---------------------------------------------- |
| **纯静态、零构建**       | 要能直接 `file://` 双击打开 | 不能用 `fetch` + JSON，数据一律写成 `.js` 挂 `window.XXX` |
| **三个站文件夹不能挪位**    | 全是相对路径              | 门户只能加一层外链，不能搬文件                                |
| **无后端、无登录、不碰个人数据** | 隐私即卖点               | 没有账号、没有排行榜、没有存档上云；进度只在内存里                      |
| **数据与渲染分离**       | 加内容不改代码             | 新增内容＝加数据文件 + 在页面清单里登记一行                        |

「在页面清单里登记一行」是这套架构唯一脆弱的地方：**漏登记＝数据静默不加载，页面上完全看不出来**。所以有 `portal/sync.js` 专门核对这件事（见第六节）。

「不碰个人数据」有且只有一个例外：页脚的到访人数（`portal/hit.js` + `worker/`）。它只存一个自增整数，不记 IP、不写 cookie、不存 UA。这条线是刻意画在这里的——**可以数「来了几次」，不能认「是谁」**。加任何超出这个范围的东西，都算破坏约束。

### 三个站各自的「页面清单」

| 站  | 清单在哪                                            | 怎么加                                            |
| -- | ----------------------------------------------- | ---------------------------------------------- |
| 卷一 | `穿越求生指南/js/data-manifest.js`                    | 数组里加一行路径                                       |
| 卷二 | `生在何朝/index.html` 的 `PACKS-BEGIN / PACKS-END` 段 | 加一行 `<script src="data/packs/xx.js"></script>` |
| 卷三 | `如果当时/index.html` 的 `<script>` 列表               | 同上                                             |

卷三必须注意顺序：`data/*.js` 在 `js/engine.js` **之前**加载，且新包要排在原包**之后**——否则会被原题库覆盖。

## 五、加一份新内容的完整流程

以"给卷二加一卷事件"为例：

```bash
# 1. 新建数据文件（不要改老文件）
#    生在何朝/data/packs/97-new.js
#    文件末尾必须写 }) (window.PACK_BASE);  写错名字不报错、静默失效

# 2. 在页面清单里登记一行
#    生在何朝/index.html 的 PACKS-END 之前
#    <script src="data/packs/97-new.js"></script>

# 3. 同步门户数字（必跑）
node portal/sync.js

# 4. 跑测试
node 生在何朝/tools/test-eras.js      # 十九朝回归，看人均抉择数有没有异常
node 生在何朝/tools/test-map.js       # 改动 geo.js 后必跑
node 生在何朝/tools/audit.js          # 事件可达性：有没有写进去却抽不到的
node 生在何朝/tools/why-dead.js       # 上面报了死内容时，查它为什么死
node 生在何朝/tools/hint-check.js     # hint 写的代价与实际 effects 对不对得上
node 穿越求生指南/tools/audit.js      # 卷一次目与渲染
node 如果当时/tools/smoke.js          # 卷三冒烟，看错误数与越界数
node 如果当时/tools/reach.js          # 卷三题库可达性
node 如果当时/tools/balance.js        # 卷三数值平衡：金钱净额、四维分位、称号分布

# 5. 重新打包
node portal/pack-deploy.js
```

卷一同理：新文件 → `js/data-manifest.js` 加一行 → `node portal/sync.js`。

**为什么补内容一律新开文件**：`registerEra` 对相同 id 是合并语义（元信息覆盖、`blocks` 追加），所以补卷永远新开一个文件，不动原文件——改动可回退，也不会把原文案搅乱。

**卷二往 `eraEvents` 里塞事件，必须用 `concat`，不许直接赋值**：

```js
B.eraEvents.qin = (B.eraEvents.qin || []).concat([ ... ]);   // 对
B.eraEvents.qin = [ ... ];                                   // 错，会把前面所有包整个顶掉
```

这条不是洁癖。2026-11 盘点时发现，早期四个包（`50–53`）共 182 条事件全部被后来的重写稿（`60–63`）这样顶掉，**一条都没跑过**，而页面上完全看不出来——数据在文件里躺着，玩家一次也遇不到。现在 `sync.js` 会逐个文件快照比对，谁顶掉了谁、多少条，直接报出来。

## 六、两个必跑的脚本

### `node portal/sync.js` — 数据核对 + 统计

做三件事：核对三站 `data/` 里的文件是否都挂进了页面（漏挂 = 静默不加载）；把三站数据真跑一遍统计数字；写出 `portal/stats.js`。

门户上的数字全部是 `[data-stat]` / `[data-stat-cn]` 钩子，从 `stats.js` 读，**不要再手改 `index.html` 里的数字**。

```bash
node portal/sync.js             # 核对 + 统计 + 写文件
node portal/sync.js --check     # 只核对，不写文件（CI 口径，出错退出码 1）
```

体检项：漏挂、时代块为空、六章缺失、事件 id 重复、class 名非法。

### `node portal/pack-deploy.js` — 打包上线

按**排除法**复制到 `_deploy/`（排除 `.workbuddy`、`shots`、`tools`、`minigame`、`node_modules`、`*.md`、隐藏文件、打包脚本自身），然后校验五个页面的每一个引用都能对上（中文名、大小写），最后报体积对照免费档限制。

用排除法而不是白名单，是因为白名单漏一个数据包线上就静默少内容，排除法漏了顶多多传几 MB——**宁可多传，不可少传**。

```bash
node portal/pack-deploy.js            # 重建 _deploy/
node portal/pack-deploy.js --check    # 只校验现有 _deploy/
```

当前产物：**262 个文件 / 4.1 MB**（2026-11-02 二次体检后：剔除图标废稿、补 og / 404）（免费档限制 1000 文件、单文件 25 MiB）。

## 七、后续怎么上线

### 本地预览

双击根目录 `index.html` 即可，不需要任何环境。  
想看 `http://` 效果（更接近线上）：

```bash
cd 人类生存网站 && python -m http.server 8080
# 打开 http://localhost:8080
```

### 上线到 Cloudflare Pages（免费，不需要信用卡）

**线上地址：<https://human-survival.pages.dev>**（2026-11-03 上线）

**方式一 · wrangler 命令行直传（当前实际用法）**

`_deploy/` 由打包脚本产出，用 wrangler 直接上传为 Pages 项目：

```bash
npm i -D wrangler          # 仅首次，装在 worker/ 目录
npx wrangler login         # 仅首次，浏览器授权
node portal/pack-deploy.js # 打包出 _deploy/
cd worker
npx wrangler pages deploy ../_deploy --project-name human-survival --branch main --commit-dirty=true
```

- 项目创建：`npx wrangler pages project create human-survival --production-branch main`（已建过）
- `--branch main` 使这次部署成为生产部署，主域名指向它；不带则只出预览域名
- Dashboard 入口：Compute → Workers & Pages → `human-survival`
- 新版 dashboard 的「Create application」默认走 **Workers** 流程（有 `npx wrangler deploy`），不是 Pages——认准 **Build output directory** 字段才是 Pages

**方式二 · 网页拖拽（不装命令行时）**

Workers & Pages → Create → Pages → **Upload assets** → 把 **`_deploy` 文件夹本身**拖进上传框 → Deploy。
⚠️ 别压成 zip：Windows 右键生成的 zip 用系统编码，中文目录名上传后会乱码、线上 404。
拖文件夹是浏览器逐个读原文件，中文名原样保留。

**代码同步在 GitHub**：<https://github.com/ailisi1/human-survival>（主分支 `main`，
仓库协作者 sxhhliu）。仓库用于备份与协作，不参与 Pages 构建；想要「push 即部署」
需在 Pages 项目 Settings → Git 里另连（当前未连）。

### 更新内容

改了数据之后，先跑一遍核对（会算出最新条数并写 `portal/stats.js`）：

```bash
node portal/sync.js
```

**上线**：提交推送（备份），再 wrangler 直传（部署）：

```bash
git add -A && git commit -m "说明改了什么" && git push
cd worker && npx wrangler pages deploy ../_deploy --project-name human-survival --branch main --commit-dirty=true
```

**拖拽部署**：先打包再拖。

```bash
node portal/pack-deploy.js   # 产出 _deploy/
```

> 注意：仓库里 `.gitignore` 排除了 `_deploy/`（构建产物不入库）与
> `生在何朝/assets/icon/`（图标废稿）。改数据时别把这两个目录加回来。

然后回到 Cloudflare 项目页 → **Create new deployment** → 重新拖 `_deploy` 的内容。每次部署都会生成新版本，可回滚到任一旧版本。

### 需要注意的几件事

- **中文路径没问题**：文件名是中文不影响，浏览器会自己编码，已验证全部返回 200。
- **不要指望 `_deploy` 里的东西能改**：它是产物，下次打包会被整个删掉重建。
- **`_deploy` 不含任何 `.md`**：策划案、本 README 都不会传上去。
- **自定义域名**：Pages 项目 → **Custom domains** → 添加自己的域名，按提示改 DNS。域名本身要花钱（约 ¥60–100/年），但 Pages 托管免费。
- **唯一已知的 404** 是 `favicon.ico`——门户和各站都已用内联 SVG 图标，不影响显示，只是浏览器会自动请求一次。

### 加一个访问计数（上线后做，约 10 分钟）

门户页脚那行「已有 N 人到访」不是写死的，来自一个独立部署的小 Worker。

**为什么单独一个 Worker，而不是 Pages Functions**：Pages Functions 要走 git 构建或 Wrangler 上传才会被编译，用「拖文件夹」上传的产物里放 `functions/` 是不生效的。独立 Worker 没这个限制，也方便单独换。

步骤（详细截图级说明见 `worker/README.md`）：

1. 后台 → **Storage & Databases** → **KV** → Create，命名 `renjian-hit`
2. **Workers & Pages** → Create → Worker，命名 `renjian-hit`，把 `worker/index.js` 贴进去，Deploy
3. **Settings → Bindings → KV namespace**，变量名必须一字不差是 `HIT`
4. **Settings → Variables**，加 `ALLOW_HOSTS` = 你的域名（如 `renjian3.pages.dev`）。不设等于谁都能调，正式上线务必填
5. 把 Worker 地址填进 `portal/hit.js` 的 `ENDPOINT`，再 `node portal/pack-deploy.js` 重新上传

**没配也能照常上线**：`portal/hit.js` 里 ENDPOINT 还是占位符时脚本直接返回，页脚那行是 `hidden`——不留空行、不报错、不影响双击打开。

**口径**：不记 IP、不写 cookie、不存 UA，只有一个自增整数；同一浏览器同一天只上报一次，所以是「按日去重的到访人次」，不是 PV。免费 KV 每天 1000 次写，即一天最多记约 1000 个新到访，超了数字停住但不报错。

**想看更细的**（来源、热门页面、地区、设备）去 Pages 项目里开 **Web Analytics**：免费、零代码、不用 cookie，和上面那个数字互不干扰。

### 以后要加登录怎么办

现在的架构是纯静态 + 零后端（唯一例外是那个只记整数的计数 Worker），这是它能免费、能双击打开、能不去碰个人数据的原因。一旦加登录：

- 需要后端（用户表、会话），免费档通常仍够用，但要选方案（Cloudflare Workers + D1 / Supabase 等）；
- 会开始承担数据合规责任（隐私政策、数据删除）；
- 本地 `file://` 双击打开的方式会失效，只能走服务器。

所以当前决定：**先不加登录**。要加的时候，建议只给"存档同步"这一个功能加，别动内容页。

## 八、写作与代码口径（改内容时请遵守）

### 文字

|   |   |
| - | - |

- 浅近白话打底，关键处用当时词汇并加小注（卷二写作 `{{词|注释}}`）。
- **禁现代词**：资源、效率、战略、人脉值、好感度、升级、属性。
- 残酷事实保留，但用记事体：保留事实、删掉细节、不抒情、不弹确认框。
- JS 字符串里表示中文引语用 `「」`，不要用 ASCII 双引号。

### 代码

- 数据文件一律 `.js` 挂 `window.PACK_XXX`，**不用 JSON + fetch**（`file://` 下会 CORS）。
- 条件表达式用结构化对象 `when:{}`，**不用 eval**（安全、可序列化、可存档）。
- 随机数必须种子可复现，否则千局对照算不了。
- 颜色语义按中文习惯：**红＝涨／得，绿＝跌／失**。
- 卷二的舆图是**示意图**，多边形按里至粗略摆放并标注"非按里至"，不画精确边界；改 `geo.js` 坐标后必跑 `test-map.js`。

## 十、约定：以后每个项目都要有 README

本项目确立一条通用约定——**每个项目根目录都要有一份 README，至少写清四件事**：

1. **想法**：这个项目为什么存在，要解决什么问题；
2. **是什么**：有哪些模块／卷／页面，各做什么；
3. **文件夹说明**：哪个目录放什么，哪些是数据、哪些是产物、哪些不上线；
4. **怎么上线**：打包命令、部署步骤、更新流程、已知限制。

新项目开工时先写骨架，做完再补实。README 一律不参与打包（`pack-deploy.js` 排除所有 `.md`）。
