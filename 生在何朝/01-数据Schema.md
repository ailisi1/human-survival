# 生在何朝 · 数据 Schema v1

> 目标：把"历史"变成可执行的数据。定完这一份，剩下的就是填内容。
> 格式选 `.js` 挂全局变量（不用 JSON + fetch），这样双击 `index.html` 用 `file://` 就能跑——和《穿越求生指南》踩过的坑一致。

## 一、包结构

一个朝代的全部内容 = 一个 pack 对象。

```js
window.PACK_MING = {
  meta:   { id:"ming", name:"明", years:[1368,1644], capital:["南京","北京"] },
  reigns: [ /* 年号表，用于把公元年转成"万历十四年" */ ],
  classes:[ /* 阶层池定义 */ ],
  prices: { /* 物价表 */ },
  titles: { /* 职官、爵位 */ },
  persons:[ /* 人物姓名池，用于随机生成姓名 */ ],
  events: [ /* 事件数组 */ ]
}
```

## 二、数值系统

### 2.1 明面六项

| key | 名称 | 范围 | 初始（按阶层浮动） | 说明 |
|---|---|---|---|---|
| `body` | 身体 | 0–100 | 60–90 | 每年自然 −0.6~−1.2；≤0 即死 |
| `silver` | 银钱 | 可为负 | 0–3000 | 单位"两"，两位小数 |
| `field_wet` | 水田 | 0–∞ | — | 亩 |
| `field_dry` | 旱地 | 0–∞ | — | 亩 |
| `grain` | 存粮 | 0–∞ | — | 石 |
| `knowledge` | 学识 | 0–100 | 0–20 | 读书线门槛 |
| `fame` | 声望 | −50–100 | −5~40 | 乡里评价 |

面板合计显示：`田产 = field_wet + field_dry`。

### 2.2 隐藏四项

| key | 名称 | 作用 |
|---|---|---|
| `grudge` | 仇怨 | 0–100，达到阈值触发报复事件 |
| `favor` | 恩义 | 0–100，达到阈值解锁"求人"选项 |
| `official` | 官声 | −50~100，只影响仕途考语 |
| `luck` | 气运 | −10~+10，随机修正，永不显示 |

### 2.3 其他状态

| key | 类型 | 说明 |
|---|---|---|
| `flags` | Set\<string\> | 剧情标记，如 `married` `sold_daughter` `jinshi` |
| `flagsOn` | {flag: 年} | 标记生效的年份，用于"十年前的事"判定 |
| `debt` | {amt, rate, dueYear} | 负债，到期强制结算 |
| `persons` | Person[] | 家人、师友、仇家 |
| `line` | string | 当前职业线 |
| `office` | {rank, title} | 现任职官 |

### 2.4 兵权四项

出身之外另有一套"打天下"的数，只有走到那个份上才看得见。

| key | 名称 | 范围 | 说明 |
|---|---|---|---|
| `troops` | 私兵 | 0–∞ | 家丁。自己养，岁饷 2.2 两/人；欠饷即散 |
| `command` | 官军 | 0–∞ | 朝廷的兵。出兵时只按 0.3 计入兵力 |
| `morale` | 军心 | 0–100 | 向 50 回落；欠饷 −9；改朝换代时最要紧 |
| `grade` | 官品 | 0–9 | 0 为无官，1 为一品。只进势力公式与授印门槛 |

派生值（不存进存档，实时算）：

```js
force  = troops + command * 0.3
might  = force/40 + fame*0.25 + GRADE_W[grade] + (field_wet+field_dry)/25 + silver/2000
```

`GRADE_W = [0,34,28,22,17,12,9,6,4,2]`（下标即 grade）。

**起兵判定**（`canRebel`）：`age ≥ 21`、`force ≥ 1200`（`grade === 0` 时须 `≥ 2200`）、`might ≥ 50`，且 `flags` 无 `rebelAsked`。

**胜算**（`rebelChance`）：`p = 0.01 + force/20000 + might/700 + (year≥1628 ? 0.15 : 0) + (morale−50)/400 + luck*0.008`，夹在 `[0.02, 0.35]`。

另外 `ledger: { battles, rebelWin, founded }` 记这一生打过几仗、有没有坐上那把椅子。`founded` 会让墓志铭、舆图着色、千局对照同时改口。


## 四、前置条件 `when`

用结构化对象，不用 eval（安全 + 可序列化）。

```js
when: {
  minAge: 16, maxAge: 45,
  minSilver: 5, maxSilver: 200,
  minBody: 20,
  minFame: 10,
  lineIn: ["exam"],
  classIn: ["gentry"],
  flagHas: ["married"],
  flagNot: ["sold_field"],
  debtExists: true,
  yearMod: 3,                 // 公元年 % 3 == 0（科举逢子午卯酉年乡试）
  anyOf: [ {...}, {...} ],    // 满足其一
  allOf: [ {...} ]            // 全部满足（默认多个字段即"全部满足"）
}
```

所有条件字段都是可选的，缺省即不限制。

## 五、选项对象

```js
{
  text: "卖女",
  hint: "银钱 +12 两；声望 −15",           // 必须写代价，不藏
  need: { minSilver: 0 },                  // 该选项出现的附加条件（不满足则整条不显示）
  hide: { flagHas: ["sold_daughter"] },    // 满足则隐藏（不是灰掉，是不出现）

  effects: [
    { k:"silver", v:+12 },
    { k:"fame",   v:-15 },
    { k:"grudge", v:+5 }
  ],

  setFlag:  ["sold_daughter"],
  kill:     null,                          // "self" 则本人即死
  then:     "你没敢看她的眼睛。",            // 结算后的一句话

  schedule: [                              // 延迟后果：十年后回响
    { inYears: 10, eventId: "ming.memory.daughter_returned" }
  ]
}
```

### 5.1 效果原子

| 原子 | 含义 |
|---|---|
| `{k:"body", v:-12}` | 身体增减 |
| `{k:"silver", v:+12}` | 银钱增减 |
| `{k:"field_wet", v:-5}` | 水田增减 |
| `{k:"grain", v:-3}` | 存粮增减 |
| `{k:"knowledge", v:+6}` | 学识增减 |
| `{k:"fame", v:-15}` | 声望增减 |
| `{k:"grudge"/"favor"/"official"/"luck", v:n}` | 隐藏值 |
| `{k:"addPerson", v:{name,role,rel,age}}` | 新增人物 |
| `{k:"killPerson", v:"daughter2"}` | 某人死亡 |
| `{k:"debt", v:{amt:20, rate:0.02, dueYear:+3}}` | 立债 |
| `{k:"line", v:"exam"}` | 转职业线 |
| `{k:"troops", v:+300}` | 私兵增减（正为募，负为散） |
| `{k:"command", v:+1200}` | 所辖官军增减（授印 / 解兵柄） |
| `{k:"morale", v:-8}` | 军心增减 |
| `{k:"grade", v:2}` | **置**官品（绝对值，非增量）。授参将即 4，授总兵即 2，革职即 0 |

### 5.2 延迟后果

两种写法：

```js
schedule: [
  { inYears: 3,  effects:[{k:"silver", v:-32}], note:"三年本息到期" },
  { inYears: 10, eventId:"ming.memory.daughter_returned" }
]
```

引擎把 `schedule` 压进 `pending` 队列，到年份自动执行。**这是"十年回响"的全部实现**，也是这个游戏最有味道的机制。

### 5.3 死亡

```js
{ text:"随军南下", kill:"self", then:"江上起了雾，你没再回来。" }
```

死亡不弹窗、不解释、不劝退，直接进墓志铭卡。

### 5.4 概率判定 `resolve`

用于"考得上考不上"这类交给学识与运气的场合，不写死。

```js
{
  text: "照常去考",
  hint: "盘缠 0.3 两；学识越高越有把握",
  effects: [{ k:"silver", v:-0.3 }],
  resolve: "examPass",
  params: {
    base: 0.12,              // 基础概率
    perKnowledge: 0.006,     // 每点学识加成
    cap: 0.62,               // 上限
    onPass: ["shengyuan"]    // 通过后置标记
  }
}
```

规则：`p = min(cap, base + knowledge × perKnowledge)`，再加 `luck × 0.01`。

#### 内建判定 `resolve: "rebel"`

起兵不由数据包写，由引擎生成，因为它要看的是那一刻的全部军情，写不进静态文案。

```js
{ text: "起兵", hint: "成败一次定。看着" + 判词 + "；输了，不只是你一个人死", resolve: "rebel" }
```

判词由 `rebelChance` 分档给出：`十死一生 / 不过一成 / 约两成 / 近三成 / 三成有余`。**别在 hint 里写精确百分比**——那是把皇帝当成赌桌。

成功：置 `flags: rebelWin`、`ledger.founded`，私兵 ×1.6、官军 6000、银 +8000、声望 100，并 `pending` 两条后续事件（`+3y` 封侯收兵、`+9y` 国本未定）。

失败：`rng < 0.45` 则族诛（全家人 `alive = false`，`die("兵败")`）；否则抄没田产、银去八成、`flags: rebelFailed`，人不死。

### 5.5 赌博分支 `gamble`

用于盐引、从军、起事、大疫这类"赢了下半辈子，输了没下半辈子"的选项。

```js
gamble: {
  winChance: 0.6,                       // 或 loseChance
  win:  [ {k:"silver", v:+200} ],
  lose: [ {k:"silver", v:+20} ],
  winNote:  "到岸价好，你赚了八十两。",
  loseNote: "在卫辉被扣了两车。",
  deathChance: 0.22,                    // 独立死亡判定，可与胜负并存
  cause: "疙瘩瘟"
}
```

**写赌博的两条规矩**：
1. 胜负两边的文案一样长、一样冷。不许把"赢"写得比"输"精彩。
2. `lose` 里允许出现 `{k:"kill", v:"self"}`。死亡是选项，不是惩罚。

### 5.6 特殊结局卡 `epitaph`

极短命的局（溺婴、幼年夭折）不必走完整回顾流程，直接出卡片：

```js
epitaph: {
  name: "无名",
  line: "生三日而卒",
  verse: "祖母说，家里已经有两个姐姐了。"
}
```

## 八、回合生成引擎（伪代码）

```js
function nextTurn(state) {
  // 1. 推进年份
  state.year += spanOf(state.age);     // 按年龄段取 2/3/4/5 年
  state.age  += spanOf(state.age);

  // 2. 结算存量（不经过事件，每年静默发生）
  settleYearly(state);                 // 田产产出、赋役扣粮、身体衰减、债务计息

  // 3. 死亡判定
  if (state.body <= 0) return die(state, "病殁");
  if (rollMortality(state)) return die(state, causeOf(state));

  // 4. 抽事件
  const pool = allEvents
    .filter(e => match(e, state))       // 朝代/年份/年龄/阶层/职业线/条件
    .filter(e => !usedRecently(e, state));

  const picked = weightedSample(pool, 1 + (state.age > 16 ? 1 : 0));
  return { year: state.year, age: state.age, events: picked };
}
```

### 8.1 匹配与抽取（v0.7 起）

硬过滤（`matchEvent`，全在 `js/engine.js`）：

| 字段 | 含义 |
|---|---|
| `hidden` | 直接排除，由引擎在特定时机塞进队列 |
| `once` | 本局用过就不再出 |
| `era` | 必须等于当前朝代 |
| `years` | 当前年份落在 `[起, 止]` |
| `age` | 当前年龄落在 `[起, 止]` |
| `sex` / `class` / `line` / `area` / `notArea` / `path` | 身份与地理限制 |
| `when` | 结构化条件，`testWhen` 逐项判定 |

抽法分三层，顺序固定：

1. **临期优先（应到）**
   在"本局还没露面、又有 `years`"的事件里，挑**离年份截止最近**的那一条，直接递到玩家面前；截止只剩 1 年时递两条。
   没有年份窗口的，则从"离 `age` 上限最近"的日常事件里挑一条——只在每回合发 3–4 条的成年期启用。幼年一回合只发一条，让这个位置占掉就成了一条道走到黑。
2. **久候加权**
   剩下的位置用加权抽签，权重 = `weight × (1 + min(6, 久候回合数) × 0.25)`。够格却没抽到，每多等一回合加一档；抽到归零。上限 2.5 倍。
3. **题材新鲜度**
   本回合递出去的题材，往后 3 回合权重 ×0.45。只降权、不禁出——禁出会造死内容，降权不会。
4. **题目去重**
   最近 9 条出过的不重出；池子里剩不到 3 条时放开。

每回合发几条：16 岁后 3–4 条，8–16 岁 2 条，8 岁前 1 条。

**为什么要有第 1 层**：同池常年两三百条、权重合计两三千。一条权重三十的大事，每回合只占百分之一；而它一辈子可能只够格两三个回合，乘起来期望不到一次——写进去等于没写。2026-11 盘点时 1448 条里有 37 条从未出现过，全是这么死的：靖康、澶渊、马嵬、淝水、采石、剃发、度田。

**为什么久候加权只给到 2.5 倍**：2026-11 补完天灾后做过一次全库体检，天灾条数占 4.1%，命中占比却到 11.9%（超配 2.9 倍），官府 249 条反倒只占 7.8%。查下来两头合力：只有"年龄窗口宽、无 once、无阶层限制"的常年事件能把久候吃满，而带年份窗口的事件被第 1 层直接递走、久候随即清零。原来给到 4.2 倍，等于系统性偏袒宽窗事件。降到 2.5 倍、并加第 3 层之后，天灾命中降到 10.5%，各题材回到条数占比的两倍以内。**加权是补救，不该反过来定调。**

**写内容时的三条推论**：

- 窄窗事件现在一定会被玩家遇到，不必为了"更容易抽到"去放宽 `years`——放宽反而让史实失真。
- 反过来，`age` 上下限决定"哪些出生年的人能遇到它"。事件若发生在朝代建立后 16 年内，玩家那时还没成年，必须把 `years` 放宽到"余波期"或下调 `age`，否则对任何玩家都不可达。夷陵（221，三国起于 220）、好水川（1041，西夏起于 1038）、郾城（1140，南宋起于 1127）、剃发（1645，清起于 1636）都是这个问题。
- **限得越多，基础权重越要给高**。`area` 限到一个州，命中面就只剩十三分之一；再叠 `class`、`sex`、`when`，权重十几的写下去，一局期望不到 0.1 次。全库现有 409 条受限事件，其中 119 条 weight < 12，是最容易变成"看得见摸不着"的一批。补完天灾后实测掉的四条——盐井（限益州）、荒年手艺（`maxGrain`）、典妻（男 + `maxGrain`）、首级（男 + `minMartial`）——都是这一类，靠提权重救回来的。判断标准很简单：**限制条件越多，weight 越该往上加**。

**`minGrade` 与 `minOfficial` 的区别**：多数"做官"路径只加官身数值（`official`），不写品级（`grade`）。写"要求有官身"必须用 `minOfficial`；写 `minGrade` 的条件恒为假，事件永远抽不到——磨勘、公使钱、到任规三条就是这么死掉的。

### 8.2 年度静默结算

| 项 | 公式 |
|---|---|
| 田产产出 | `(field_wet×1.8 + field_dry×0.9) 石 − 赋役` |
| 赋役 | 万历后按亩折银，约 `field×0.05 两`；三饷时期 ×2.5 |
| 身体自然衰减 | `−0.8`（40 岁后 `−1.2`，60 岁后 `−1.8`） |
| 债务 | `debt.amt × (1+rate)^n`，到期强制扣银，不足则卖田 |

## 九、存档结构

```js
{
  v: 1,
  seed: 1738291042,          // 随机种子，用于复现与千局对照
  state: { ...数值与人物... },
  turnIndex: 7,
  pending: [ ...延迟后果... ],
  usedEvents: [ ...已触发 id... ],
  log: [ {year, age, eventId, choice} ],  // 用于生成一生年表
  dead: false
}
```

localStorage 键：`shz.run.current`（当前局）、`shz.runs`（最近 20 局摘要）。

**随机数必须是可复现的**（种子 + 伪随机），否则"千局对照"没法算。

## 十、千局对照

```js
function simulate1000(state) {
  const base = snapshot(state);      // 从当前开局复制
  return Array.from({length:1000}, (_, i) => {
    const s = restore(base, seed + i);
    while (!s.dead) step(s, /*autoChoice*/ true);   // 自动选择：按权重随机
    return summarize(s);
  });
}
```

纯本地、同步、毫秒级。产出的每个指标（活到成年、成家、识字、有功名、做官、活过六十）都是一次布尔判定。

## 十一、写内容的六条硬规矩

1. **数字必须具体**。"三斗米"不是"一些粮食"。
2. **一次只写一件事**。一个事件只问一个问题。
3. **不写心理**。写"父亲的咳嗽到冬天没好"，不写"你很难过"。
4. **代价写在选项上**。`hint` 字段不许空。
5. **不设最优解**。四选项里至少两个是"都疼"。
6. **禁现代词**：资源、效率、战略、人脉值、好感度、升级、属性、性价比。

## 十二、天下数据（`js/realm.js`）

引擎只认四个函数：`mightOf / forceOf / canRebel / rebelChance`。其余全是数据，每朝一份。**接新朝时只写这一份，引擎一行不动。**

### 12.1 朝代简介

```js
BRIEF.ming = {
  name: "明", span: "1368 — 1644", capital: "南京 → 北京", founder: "太祖朱元璋",
  parts: [
    { from: 1368, to: 1398, title: "洪武", lines: ["…", "…", "…"] },
    …
  ]
}
```

`S.eraBrief(eraId, year)` 返回该年所属的那一段。**必须按年分段**：洪武年与崇祯年不是同一个明朝。每段三句，一句一事，不评价。

### 12.2 舆图

```js
MING_MAP = {
  w: 680, h: 470,
  regions: [
    { id: "huguang", name: "湖广布政司", short: "湖广", ctl: 0.8,
      pts: "382,292 442,284 …",      // SVG polygon 顶点
      label: [416, 334],             // 省名位置
      note: "…一句史实" }
  ],
  water:  [ { id: "changjiang", name: "长江", d: "M…" } ],
  walls:  [ { name: "长城", d: "M…" } ],
  capitals: [ { name: "北京", x: 500, y: 132, lx: 500, ly: 120, anchor: "middle", main: true, note: "…" } ],
  owner:  { liaodong: [[1368,"court"], [1618,"jianzhou"]], … },
  marks:  [ { id: "wo", name: "倭", x: 566, y: 340, from: 1552, to: 1566, color: "zhu", note: "…" } ]
}
```

规则：

- `pts` 是**示意图**，不是地理边界。位置关系对即可，标注"非按里至"。
- `owner` 是 `[起始年, 势力id]` 序列，取最后一个不晚于当年的项。**年份一变，颜色就变**——这是整张图的活性来源。
- `ctl`（1 腹里 / 0.6 边省 / 0.35 羁縻）留给后续做"控制力深浅"，当前只存不用。
- 画布按 region 顶点自动收紧，改坐标不会留白。

### 12.3 势力

```js
{ id: "eunuch", name: "宦官", kind: "内廷", color: "zhu",
  desc: "司礼监掌批红，东厂、锦衣卫侦伺百官。",
  power: [[1368, 6], [1402, 34], [1435, 46], [1627, 84], [1628, 12]] }
```

`power` 逐年线性过渡；`power ≤ 3` 的势力不显示（还没成气候的不该出现在榜上）。列表按当年势力降序。

### 12.4 军备

```js
MING_ARMY = [ { year: 1368, weisuo: 120, border: 30, capital: 20, gentry: 10 }, … ]  // 单位：万人
```

四项含义固定：卫所兵 / 边镇额兵 / 京营 / 乡兵民壮。取**实存**不取额数，因为明代账面与实存差着一倍。

### 12.5 官职

```js
MING_OFFICES = { central: [...], local: [...], military: [...] }
// 每项：{ name, grade, note }   grade: 1–9，0 为未入流
```

`note` 写职掌，不写评价。玩家现任那一格按 `post` / `rank` 字符串匹配高亮。

### 12.6 接第 2 朝要写什么

以唐为例：

| 表 | 内容 |
|---|---|
| `BRIEF.tang` | 武德—贞观、永徽—天宝、安史、藩镇、会昌—乾符，五段 |
| `TANG_MAP` | 十道 + 都护府；长安、洛阳；黄河、渭水、大运河南段 |
| 势力 | 朝廷、宦官（自玄宗后）、藩镇、士族、吐蕃、回鹘、南诏、粟特商团、流民 |
| 军备 | 府兵（前）→ 彍骑 → 节度使方镇兵（后），这个转换本身就是唐史 |
| 官职 | 三省六部、御史台、节度使、观察使、府兵折冲都尉 |
| 简介 | **必须写出府兵到募兵的那次断裂**，否则唐与明没有区别 |

## 十四、v0.5 增补：十九朝的数据写法

v0.4 只有明朝，数据是"一手写死的对象"。v0.5 要写 19 个政权，所以换成了**竖线分隔的字符串 DSL**。解析器在 `js/era.dsl.js`，成型数据挂在 `S.BOOK[eraId]`。

### 14.1 为什么用字符串

一个朝代的完整天下数据，写成对象要 800 行，写成竖线串约 100 行。19 朝 × 700 行 ≈ 一万三千行，写不完也改不动。字符串形式的代价是解析器必须写对——所以 `tools/test-eras.js` 里专门有一段校验：每朝至少要有政区、势力、兵备、官职四样非空。

### 14.2 `S.book({...})` 的字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 十九朝 id，与 `S.ERAS` 一致 |
| `name` `span` `capital` `founder` `money` | string | 基本信息 |
| `selfId` | string | 本朝在政区归属里的自称（辽 `liao`、夏 `xia`、金 `jin`、五代 `liang+jin+han+zhou`）。省略则默认 `court` |
| `brief` | `[起, 止, 小标题, [段落...]]` | 朝代简介，按年份分段，3–6 段 |
| `reigns` | `"年号|起|止|帝王"` | 年号表，用于把公元年折成"贞观三年"这类说法 |
| `regions` | `"geo|名|简称|控制力|注|年:归属,..."` | 政区 |
| `water` | `["huanghe", ...]` | 用到哪些水系 |
| `walls` | `[...]` | 用到哪段长城 |
| `caps` | `"名|geo|dx,dy|是否京师|注"` | 都城与陪都 |
| `factions` | `"id|名|类|色|描述|年:值,..."` | 势力及其强弱曲线 |
| `army` | `{segs:["名称|注"], pts:["年:中央,边军,私兵,牙兵"]}` | 兵备 |
| `offices` | `"名|品|注"` | 中央 / 地方 / 军职三张表 |
| `places` | `"州|府|县,县"` | 出生地池 |
| `marks` | `"字|geo|dx,dy|起|止|注"` | 地图上的名胜与事件标记 |
| `unrest` | `"起|止|加成"` | 乱度区间，0–1 |

### 14.3 政区归属的归一化

政区串的最后一段是 `年:归属` 的序列，按年份推进：

```
"youzhou|南京析津府|南京|0.8|燕京，汉地财赋所出。|916:liao"
"beizhili|北直隶|北直|0.9|顺天府，京师所在。|1368:court"
```

归属 id 有两种：`court`（朝廷）和具体势力 id（`liao` `xia` `jin` `mongol` `jianzhou` `me` …）。

**问题**：辽、西夏、金把自家腹地写成自家名号，图上就会被判成"不在朝廷之手"。

**做法**：`S.book` 收集该朝出现过的所有归属 id，若只有一个且不是 `court`，就认作本朝，存进 `B.selfId`；`S.regionOwner` 返回前先把 `selfId` 折成 `court`。五代有四个政权轮流坐庄，所以显式声明 `selfId: "liang+jin+han+zhou"`。

### 14.4 每朝专有事件：`B.eraEvents[eraId]`

```js
(function (B) {
  B.eraEvents = B.eraEvents || {};
  B.eraEvents.qin = [ { id: "q2.fuji", ... }, ... ];
})(window.PACK_BASE);
```

`S.getPack(eraId)` 的合并顺序：`common` → `periods[时段].events` → `PACK_<ERA>.events`（若有）→ `eraEvents[eraId]`。

事件对象与 v0.4 完全一致（`id` `cat` `title` `text[]` `options[]`，可选 `age` `years` `era` `weight` `once` `sex` `when`），**不需要写 `era` 字段**——文件本身已经限定了朝代。

命名前缀约定（只为可读，不参与逻辑）：

| 前缀 | 朝 | 前缀 | 朝 |
|---|---|---|---|
| `q2.` | 秦 | `wj2.` | 西晋 |
| `w2.` | 西汉 | `ej2.` | 东晋十六国 |
| `x2.` | 新 | `n2.` | 南北朝 |
| `e2.` | 东汉 | `su2.` | 隋 |
| `s2.` | 三国 | `t2.` | 唐 |
| `wd2.` | 五代十国 | `b2.` | 北宋 |
| `l2.` | 辽 | `x2.`（夏）| 西夏 |
| `j2.` | 金 | `ns2.` | 南宋 |
| `y2.` | 元 | `qi2.` | 清 |

**全站 id 必须唯一**——`once` 是靠 id 记的，重复会让后一条永远不出现。加新事件前先跑一遍去重检查。

### 14.5 乱度 `unrest`

```
unrest: "1628|1644|0.22"
```

多个区间用逗号隔开。`S.unrestAt(eraId, year)` 取所有命中区间之和，封顶 0.6。引擎在五处读它：危机标记、收成、税率、士气年降、造反概率。**不要在新事件里再写 `s.year > 1628` 这种硬判断。**

### 14.6 兵备 `army.pts`

```
pts: ["916:40,10,20,5", "1055:60,20,25,10", "1125:10,2,5,3"]
```

四段依次是中央禁军、边军、私兵、牙兵/部曲（单位：千人）。`S.armyAt` 按年份线性插值，返回 `{segs, units, total}`。`total` 参与 `S.forceOf` 与 `S.mightOf`。

写成字符串而不是数组，是为了在一行里看出兵力随时间的变化趋势——**兵力曲线本身就是一朝兴衰的叙事**。

## 十五、v0.6 增补：舆图几何与新事件卷

### 15.1 舆图为什么必须共用顶点

旧写法每块地各存一组 `pts`（"x,y x,y …"），块与块之间靠手调对齐。结果是块间留缝、外圈没有海岸、改一块要顺手改三块。十九朝十九张图，改不动。

现在改成**共享顶点网格**，写在 `js/geo.js`：

```js
S.PT = { N1: [172,238], N2: [250,226], /* … */ M1: [326,296], K1: [610,268] };

S.CELL = {
  saibei: { loop: ["N3","N4","N5","N6","N7","K1","K4","M5","M1"], c: [428,244] },
  hedong: { loop: ["M5","K4","K6","L2"], c: [468,356] }
};
```

- `S.PT` 是顶点表，键名给人看（N 北缘、M 河西、K 河北、C 江淮、G 岭南、S 河西以西）。
- `S.CELL` 是地块表。`loop` 是顶点名的循环，首尾自动闭合；`c` 是标注位置，可手调，不必是几何中心。
- 相邻两块共享同一对顶点，拼起来严丝合缝，**二十四块合起来是一整片大陆，外轮廓只有一条闭曲线**。
- `S.GEO[k]` 在载入时由 `CELL` + `PT` 生成，含 `pts`（"x,y …"）、`path`（"M x y L … Z"）、`c`。

### 15.2 合并块与别名

北直隶＝幽燕＋河北，是**一块**（用的顶点就是那两块合起来的外圈）。元明清三代用整块，其余各代用拆开的两块。两者同时在图上就会叠着描两遍，所以：

```js
S.CELL_ALIAS = { beizhili: ["youzhou", "hebei"] };
```

规则只有一条、且在渲染与自检里写法一致：

- 本朝引用了 `beizhili` → 丢掉 `youzhou`、`hebei`；
- 本朝没引用 `beizhili` → 丢掉 `beizhili`，按拆开的两块画（不论那两块是"本朝政区"还是"版图外"）。

### 15.3 版图外的地名

某朝不辖此块时，图上仍要画，只是颜色淡一档。给它一个地名：

```js
S.CELL_FAR = { xiyu: "西域", saibei: "塞北", tubo: "吐蕃", dongbei: "东北诸部", /* … */ };
```

**只给地理名，不给制度名。**写"河西"可以，写"河西节度使"就错了——那是唐朝的建制，放到元的图上就是假的。

### 15.4 加一块地的步骤

1. 在 `S.PT` 里补顶点（能用已有顶点就不要再造，造一个就会与邻块错开）。
2. 在 `S.CELL` 里写 `loop`，顺时针或逆时针都行，但**全场绕向要一致**（现在统一为正向面积）。窄条地块尤其容易写反。
3. 若是合并块，登记进 `S.CELL_ALIAS`。
4. 在 `S.CELL_FAR` 里给它一个地名。
5. `node tools/test-map.js`——它会做四件事：逐朝取样查重叠、查外轮廓顶点度数是否都为 2（即闭合成一条岸线）、查绕向是否一致、查版图外地块有无地名。

`tools/test-map.js` 的输出只有两种：`无异常。` 或者一张问题清单。**改坐标后不跑这一步，等于闭着眼睛改图。**

### 15.5 水系、山、长城

```js
S.WATER   = { huanghe: { name:"黄河", d:"M…" }, changjiang: …, yunhe: … };
S.MOUNTAIN = [{ n:"秦岭", p:[[398,442],[440,440],[482,438]] }];
S.DESERT   = [{ n:"沙海", p:[[158,340],[206,352],[254,348]] }];
S.WALL     = { name:"长城", d:"M346,304 C…" };
```

- 水系、山、沙漠是**走向示意**，不是河道与等高线。山在渲染时被折成一串小尖（`ridgePath()`），尖距 22、尖高不过 6.6；密一点就成了锯齿波，看不出是山。
- 黄河的河套要画成弧，不要画成"两竖一般齐"的方框——齐了就像图上盖了个印，不像河。
- 长城只在明朝的 `walls: true` 时出现。清不修长城，故设为 `false`。

### 15.6 专有事件的卷号

`B.eraEvents[eraId]` 按卷合并，文件编号即卷号：

| 卷 | 文件 | 朝 |
|---|---|---|
| 五 | `50-era-qh.js` | 秦、西汉、新、东汉 |
| 六 | `51-era-wj.js` | 三国、西晋、东晋、南北朝 |
| 七 | `52-era-song.js` | 隋、唐、五代、辽 |
| 八 | `53-era-yq.js` | 北宋、西夏、金、南宋、元、明、清 |
| 九 | `60`–`63` | 十九朝制度与大事 |
| 十 | `64-era-e.js` / `65-era-f.js` | 十九朝风俗与生计 |

新增一卷时用 `concat` 追加，不要覆盖：

```js
B.eraEvents.qin = (B.eraEvents.qin || []).concat([ /* … */ ]);
```

文件末尾必须写成 `})(window.PACK_BASE);`——`B` 就是 `PACK_BASE`。写成别的名字不会报错，会静默什么都不发生。

事件 `id` 用小写，前缀按卷区分（`q5.`、`w5.`、`x5.`…），同一个朝里重复的 `id` 会被 `tools/test-eras.js` 之外的统计脚本查出来。

### 15.7 数值上限（新内容必须遵守）

| 字段 | 单次下限 | 说明 |
|---|---|---|
| `silver` | −14 | 全站旧内容的最大扣减就是 14 |
| `body` | −12 | 引擎里再折半；写 −25 那种会让人三十岁前死绝 |
| `field_wet` / `field_dry` | 视主题 | 一般不超过 ±16 |

`body` 由 `settleOneYear` 的"休养"（每年 +3.4）回补，`silver` 则**没有回补**——所以银钱扣得狠，玩家临终就会欠债。

### 15.8 账面永不留负数

`foldDebt(s)` 把负的银钱并进 `s.debt`（债务），账面归零。调用点有三处：年终结算、每次选择结束、以及 **`die()` 的入口**。

最后这一处是 v0.6 补的。原先"寿终"那一下直接 `die()`，不经过任何平账，于是抽测里出现"临终银 −13"。平账放在 `die()` 里，才是真正的硬约束——不管从哪里死的，账面都是干净的。
